# Understand Threat Hunting Data Sources

## Overview

Threat hunting relies on high-quality data collected from various sources across an organisation's environment. These data sources provide the visibility needed to detect suspicious activities, investigate incidents, identify attacker behaviour, and validate threat hunting hypotheses.

The effectiveness of a threat hunt largely depends on the availability, quality, and coverage of security telemetry collected from endpoints, networks, authentication systems, SIEM platforms, and threat intelligence sources.

By combining multiple data sources, threat hunters can develop a comprehensive view of their environment and identify malicious activities that may otherwise remain undetected.

---

# 1. Endpoint Data

## What is Endpoint Data?

Endpoint data consists of security events and system activities collected from devices such as:

- Workstations
- Laptops
- Servers
- Virtual machines
- Mobile devices

Since attackers frequently interact with endpoints during an intrusion, endpoint data is one of the most valuable sources for threat hunting.

---

## Information Available from Endpoint Data

### Process Activity

Provides visibility into:

- Process creation
- Process termination
- Parent-child process relationships
- Command-line execution

**Example:**

```text
powershell.exe -EncodedCommand
```

This may indicate malicious script execution.

---

### File Activity

Includes:

- File creation
- File modification
- File deletion
- File downloads

Threat hunters often investigate suspicious files and malware-related activity.

---

### Registry Activity

Windows registry events can reveal:

- Persistence mechanisms
- System modifications
- Malware configuration changes

---

### User Activity

Examples include:

- User logins
- Account changes
- Privilege usage
- Administrative actions

---

## Common Endpoint Data Sources

### Windows Event Logs

Provide visibility into:

- Authentication events
- Process execution
- Account management

### Sysmon Logs

Offer enhanced endpoint visibility.

Common Event IDs:

- Event ID 1: Process Creation
- Event ID 3: Network Connection
- Event ID 7: Image Load
- Event ID 11: File Creation

### Endpoint Detection and Response (EDR)

Examples:

- Microsoft Defender for Endpoint
- CrowdStrike Falcon
- SentinelOne
- Trellix Endpoint Security

---

## Threat Hunting Use Cases

- PowerShell abuse
- Malware execution
- Persistence mechanisms
- Privilege escalation
- Suspicious process creation

---

# 2. Network Data

## What is Network Data?

Network data provides visibility into communications between systems, applications, and external entities.

Attackers often use network communications to:

- Deliver malware
- Communicate with command-and-control servers
- Move laterally
- Exfiltrate sensitive data

Monitoring network activity helps identify these behaviours.

---

## Types of Network Data

### DNS Logs

Record domain lookup requests.

Example:

```text
Host requests malicious-example.com
```

Useful for detecting:

- Malware communication
- Command-and-control domains
- Domain Generation Algorithms (DGAs)

---

### Firewall Logs

Record network traffic allowed or blocked by firewalls.

Information includes:

- Source IP
- Destination IP
- Ports
- Protocols

---

### Proxy Logs

Track web traffic generated by users and systems.

Useful for investigating:

- Website access
- Malware downloads
- Suspicious web activity

---

### NetFlow Data

Provides network communication metadata.

Examples:

- Source address
- Destination address
- Connection duration
- Data volume

---

### IDS/IPS Logs

Generated by intrusion detection and prevention systems.

Examples:

- Signature matches
- Suspicious traffic alerts
- Known attack patterns

---

## Threat Hunting Use Cases

- Beaconing activity
- Data exfiltration
- Suspicious outbound communication
- DNS tunnelling
- Command-and-control traffic

---

# 3. Authentication Logs

## What are Authentication Logs?

Authentication logs record user login and access activities across systems and applications.

These logs help hunters identify compromised accounts, credential theft, brute-force attacks, and unusual user behaviour.

---

## Information Available in Authentication Logs

### Successful Logins

Examples:

- Username
- Login time
- Source IP address
- Device information

---

### Failed Logins

Multiple failed logins may indicate:

- Password spraying
- Brute-force attacks
- Credential guessing attempts

---

### Account Changes

Examples:

- Password resets
- Account creation
- Group membership modifications

---

### Privileged Access Events

Monitor:

- Administrative logins
- Elevated permissions
- Sensitive account activity

---

## Common Authentication Sources

### Active Directory Logs

Provide visibility into:

- Domain logins
- Account lockouts
- User management

---

### Azure Active Directory Logs

Provide cloud identity information including:

- User authentication
- Conditional access decisions
- Risk-based sign-ins

---

### VPN Logs

Track remote access activity.

Useful for identifying:

- Unusual access patterns
- Suspicious locations
- External connections

---

## Threat Hunting Use Cases

- Account compromise
- Impossible travel detection
- Brute-force attacks
- Privilege abuse
- Unusual login behaviour

---

# 4. SIEM Data

## What is SIEM Data?

A Security Information and Event Management (SIEM) platform collects, aggregates, normalises, and analyses data from multiple security sources.

SIEM systems provide a centralised platform for threat hunting and investigations.

---

## Benefits of SIEM Data

### Centralised Visibility

Provides a single location for analysing:

- Endpoint events
- Network events
- Authentication logs
- Security alerts

---

### Event Correlation

SIEM platforms correlate related activities across multiple systems.

Example:

```text
Failed logins
        ↓
Successful login
        ↓
Privilege escalation
        ↓
Data access
```

This sequence may indicate account compromise.

---

### Advanced Searching

Threat hunters can query large datasets using search languages such as:

- KQL (Kusto Query Language)
- SPL (Splunk Search Processing Language)

---

### Detection Analytics

SIEM platforms support:

- Correlation rules
- Alert generation
- Behaviour analytics
- Threat hunting investigations

---

## Common SIEM Platforms

- Microsoft Sentinel
- Splunk
- IBM QRadar
- ArcSight
- LogRhythm

---

## Threat Hunting Use Cases

- Cross-source investigations
- Timeline reconstruction
- IOC searching
- Behaviour analysis
- Attack chain investigation

---

# 5. Threat Intelligence Feeds

## What are Threat Intelligence Feeds?

Threat intelligence feeds provide information about known threats, attacker infrastructure, malware, and adversary tactics.

Threat hunters use intelligence to enrich investigations and develop hunting hypotheses.

---

## Types of Threat Intelligence

### Indicators of Compromise (IOCs)

Examples:

- Malicious IP addresses
- Domains
- URLs
- File hashes

---

### Tactical Intelligence

Provides information about:

- Attack techniques
- Exploitation methods
- Malware behaviour

---

### Operational Intelligence

Provides insight into:

- Threat actor campaigns
- Adversary operations
- Ongoing attack activities

---

### Strategic Intelligence

Focuses on:

- Emerging threats
- Industry trends
- Cyber risk analysis

---

## Intelligence Sources

### Open-Source Intelligence (OSINT)

Examples:

- AbuseIPDB
- VirusTotal
- AlienVault OTX

---

### Commercial Intelligence

Examples:

- Recorded Future
- CrowdStrike Intelligence
- Mandiant Intelligence

---

### Government and CERT Advisories

Examples:

- CISA Alerts
- CERT-In Advisories
- National Cyber Security Centres

---

## Threat Hunting Use Cases

- IOC enrichment
- Threat actor tracking
- Hypothesis generation
- Campaign analysis
- Detection improvement

# Integrating Multiple Data Sources

Threat hunting becomes more effective when multiple data sources are analysed together.

### Example Investigation

#### Endpoint Data

```text
PowerShell execution detected.
```

#### Authentication Logs

```text
Unusual login from a foreign location.
```

#### Network Logs

```text
Connection established with suspicious IP address.
```

#### Threat Intelligence

```text
Destination IP linked to a known malware campaign.
```

#### SIEM Correlation

```text
All activities correlated into a single attack investigation.
```

This combined approach provides greater context and improves detection accuracy.

# Key Takeaways

- Threat hunting depends on collecting and analysing data from multiple sources.
- Endpoint data provides visibility into processes, files, registry activity, and user behaviour.
- Network data helps identify malicious communications, command-and-control traffic, and data exfiltration.
- Authentication logs reveal account activity and potential identity-based attacks.
- SIEM platforms centralise and correlate security data to support investigations.
- Threat intelligence feeds enrich investigations with information about adversaries, indicators, and attack techniques.
- Combining multiple data sources significantly improves threat visibility and detection effectiveness.

---

# Conclusion

Threat hunting data sources are the foundation of proactive security investigations. Endpoint data, network telemetry, authentication records, SIEM data, and threat intelligence feeds each provide unique insights into attacker behaviour. By integrating these sources, threat hunters gain comprehensive visibility across the environment, enabling them to identify sophisticated threats, validate hypotheses, uncover hidden attacker activity, and strengthen organisational security.
